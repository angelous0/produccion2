Resumen del diseño

Tres bloques apilados en este orden, con todos opcionales según rol:

  1. Panel "Requiere atención" — tarjeta con gradiente (rojo si hay cosas críticas, ámbar si solo hay tirones, teal si todo bien). Solo aparece si el rol tiene algo accionable. Contenido contextual:
    • admin: Urgentes + Fallados + Paralizados
    • supervisor_acabado: Fallados vencidos + Urgentes en acabado
    • operario_costura: Urgentes en costura + Paralizados
    • supervisor_inventario: Stock bajo + Agotados
    • supervisor_corte/planificación: Urgentes + Paralizados
    • mirian: Urgentes + Paralizados
    • encargada_pt (lorena): Cortes en PT pendientes de aprobar
  2. KPIs sumarios — tarjeta blanca con 3 números grandes. Contenido también contextual:
    • admin: Activos / Urgentes / Fallados
    • omar: En acabado / Fallados / A tienda
    • raul: En costura / Urgentes / Cerrados hoy
    • inventario: Items / Ing. pend. / Salidas hoy
  3. Lista compacta agrupada — secciones por área (Producción / Inventario / Acabado / Reportar). Cada fila con icono color, título, meta, badge si aplica. Filtra por rol con puede().

Para implementar: necesito 1-2 endpoints nuevos para alimentar los contadores (ej. /api/registros/atencion?rol=... que devuelva los conteos del panel). Si no querés tocar backend ahora, primero hago todo con queries client-side (varios GET pequeños) y después optimizamos.
