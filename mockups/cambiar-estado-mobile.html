Reglas de negocio implementadas

1) Cómo se filtran los estados visibles

  • El backend devuelve todos los estados de la ruta del modelo (GET /api/registros/:id/estados-disponibles).
  • El frontend cruza con user.permisos._operativos.estados_permitidos y muestra solo los que ese usuario puede asignar.
  • El resto aparece debajo como info ("Otros estados — tu rol no los puede asignar") solo para que sepa qué viene después y a quién pedir.
  • El estado "siguiente lógico" según la ruta tiene un badge "SIGUIENTE" teal y borde para destacarlo.

2) Estados con auto-creación de movimiento

  • Estados que generan movimiento automático al cambiar: Corte, Costura, Atraque, Lavandería, Acabado.
  • Movimiento creado: servicio = nombre del estado, fecha_inicio = ahora, persona = usuario actual, cantidad = total prendas del corte.
  • El operario puede agregar una observación opcional antes de confirmar.
  • Estados de espera "Para X" (Para Corte, Para Costura, Para Atraque, Para Lavandería, Para Acabado) → NO crean movimiento. Solo cambian el estado.
  • Excepción: si ya existe un movimiento abierto del mismo servicio (sin fecha_fin), no se crea otro. Se reutiliza el existente.

3) Validaciones bloqueantes

  • Para entrar a "Para Lavandería" → el último movimiento de la etapa anterior (Costura o Atraque, lo que esté en la ruta) debe tener fecha_fin seteado.
  • Para entrar a "Para Acabado" → Lavandería debe estar cerrado.
  • Para entrar a "Almacén PT" → Acabado debe estar cerrado.
  • Si la validación falla, sheet de error (pantalla 4) con:
    • Mensaje claro de qué está bloqueando
    • Detalle del movimiento abierto que falta cerrar (servicio, persona, cantidades)
    • Botón directo "Ir a cerrar movimiento" que lleva al detalle

4) Endpoints usados

  • GET /api/registros/:id/estados-disponibles — lista de estados de la ruta + estado actual
  • GET /api/movimientos-produccion?registro_id=:id — para verificar movimientos abiertos antes de validar
  • PUT /api/registros/:id body { estado, ... } — cambia el estado (el backend valida permisos)
  • POST /api/movimientos-produccion — crear el movimiento automático cuando aplique
